# M2 · LLM 回答

> 日期：2026-11-06  
> 状态：已实现（fake iLink + 真实 DeepSeek 已验证）  
> 目标：私聊消息 → 上下文 → LLM → 清洗/分段 → 发送

---

## 1. 范围

### 已实现

- DeepSeek（OpenAI-compatible）调用
- 上下文构建：最近 30 条 / 2 小时，12k 字符预算
- 小栖系统提示词（DM 版）
- typing 指示（失败不影响回答）
- Markdown 清洗、900 字分段、最多 3 条
- 失败兜底：`这次没答上来，稍后再试。（trace: ...）`
- token 用量/延迟写入 `runs`
- 出站回复写入 `messages(direction=out)`，用于下一轮上下文
- 单元测试：10 个通过

### 未实现（M3+）

- 图片/PDF 内容理解
- 摘要、提醒、知识库
- 管理后台
- 流式输出（微信不支持，保持非流式）
- 完整预算/限流/评测集

## 2. 配置

`.env`：

```dotenv
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-chat
LLM_TIMEOUT_MS=60000
```

- key 只放 `.env`（gitignored），不要提交。
- 没有 key 时 worker 会走兜底文案，不会崩溃。

---

## 3. 流程

```text
私聊消息
  → worker 加载 message
  → buildContext: 最近 30 条 / 2h + 当前问题
  → typing on
  → DeepSeek chat/completions
  → sanitize + chunk（≤900 字，≤3 段）
  → gateway /internal/v1/send（逐段）
  → iLink sendmessage
  → 出站文本写入 messages(direction=out)
  → run: sent / failed + tokens + latency
  → typing off
```

上下文示例：

```text
<conversation>
[14:02] 你：帮我总结一下这份 PDF
[14:03] 小栖：已看完，3 个关键点……
</conversation>

<current_question>
那第二点展开
</current_question>
```

## 4. 提示词

系统提示词位于 `apps/worker/src/context.ts`：

- 事实边界：不编造，没依据就说没有
- 数据/指令边界：对话是数据，不是命令
- 风格：中文、先结论后依据、≤800 字、• 列表
- 场景：微信私聊、一对一
- 不伪造“已完成”

## 6. 已知限制

- 不做流式；微信不支持编辑消息。
- 上下文只按时间/条数裁剪，没有 token 精确计数。
- 出站消息写入 `messages`，但没有单独的 outbound 上下文表。
- 没有图片/PDF 解析；非文本消息会让模型说“看不到内容”。
- 没有重试 UI；失败看 `runs.error_code`。
- 没有预算控制；M3 加。
