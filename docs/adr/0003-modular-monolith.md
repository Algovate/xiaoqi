# ADR-0003：模块化单体，gateway 与 worker 分进程

- 状态：已接受（2026-11-06）
- 决策者：架构
- 相关：设计文档 §5.2

## 背景

v1 是单账号、少群，不值得上微服务。但长轮询和 LLM 调用有完全不同的资源模型：

- 长轮询是 35 秒挂起的 I/O，需要稳定、不能被重启打断；
- LLM/工具是几秒到几十秒的 CPU/网络混合任务，需要独立扩容和重启；
- 发送需要集中限流，不能每个 worker 各自发。

## 决策

一个代码仓库、一个 PostgreSQL，拆三个进程：

- `gateway`：登录、轮询、游标、发送、typing、限流；
- `worker`：消息处理、Agent、工具、RAG、摘要；
- `api`：管理后台 API + SSE。

进程间通过数据库 + Redis 队列通信；worker 不持有 iLink token，发送统一调 gateway 的内部接口。

## 后果

**正面**

- 重启 worker 不影响收消息；重启 gateway 不丢已入队任务；
- 发送限流只有一处，避免多进程打爆；
- 后续多账号可按账号分片 gateway；
- 仍是一个仓库、一套部署，认知负担低。

**负面**

- 多两个进程，本地开发需要编排；
- 进程间多一次 HTTP 调用；
- 需要处理 gateway 不可用时的发送重试。

**缓解**

- Docker Compose 一键起；
- 内部接口用共享密钥 + 只监听 Docker 网络；
- 发送失败进 outbox，gateway 恢复后重试。

## 何时拆分

当出现以下任一情况再考虑服务化：

- 单账号消息量 > 50 msg/s；
- 多账号 > 10 个；
- worker 需要独立扩到 3 台以上；
- 团队 > 3 人并行开发。
