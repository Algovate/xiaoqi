# ADR-0002：群内默认只响应 @ 与命令

- 状态：已接受（2026-11-06）
- 决策者：产品/架构
- 相关：设计文档 §3.1、§7.6

## 背景

iLink 会把 bot 所在群的消息都推给 bot。技术上可以做到“每条消息都看、都回”，但群聊场景有三个现实问题：

1. **打扰**：一个每句话都接话的 bot 会被很快踢掉；
2. **隐私**：成员没有预期自己的闲聊被 AI 处理；
3. **风险**：全量回复更容易触发限流、内容审核和平台处罚。

## 决策

默认触发策略：

- `@bot` + 文本；
- `/` 命令；
- 引用 bot 消息继续追问；
- 私聊。

普通群消息**只入库、不响应**；入库也仅用于“被 @ 时的上下文”和“总结”，默认保留 48 小时（原始消息 7 天）。

管理员可以在后台开启 `allMessages`，但不作为默认，且开启时显示风险提示。

## 后果

**正面**

- 群体验可控，误触发少；
- 隐私叙事清晰：“你 @ 它，它才处理”；
- 频率和成本可预测。

**负面**

- 不能做“自动接话”“关键词监控”类玩法；
- 用户需要学习 @ 或命令；
- 总结功能仍会读取未被 @ 的消息，需要在入群时明确告知。

**缓解**

- 入群欢迎 + `/privacy` 说明读取范围；
- 管理员可关闭上下文读取，只保留“当前问题 + 引用”；
- 提供 `/reset` 与后台清除。
