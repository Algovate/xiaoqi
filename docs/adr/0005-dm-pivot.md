# ADR-0005：v1 从群助手转为微信私聊助理

- 状态：已接受（2026-11-06）
- 决策者：产品/架构
- 相关：[Phase 0 结果](../phase0-results.md)、[DM v1 设计](../design.md)

## 背景

Phase 0 实测：

- 扫码登录的 iLink bot 是 `...@im.bot` 插件身份，不能加入普通微信群；
- iLink 不向该身份推送群消息；
- 企业微信官方机器人只支持内部员工群，外部客户群（含微信用户）不支持双向对话；
- 私聊通道完整可用：文本、图片、PDF、引用、发送、媒体解密均验证通过。

原 v1 的核心假设“群里的 AI 助手”不成立。

## 决策

v1 收缩为**微信私聊 AI 助理**：

- 用户直接私聊 bot，不需要 @、不需要拉群；
- 上下文按用户隔离，`conversation_key = dm:<wx_user_id>`；
- 保留 Agent、RAG、提醒、媒体、后台；
- 群相关模块（群锁、@ 解析、群成员、群回复 resolver、群摘要）不进入 v1；
- 群聊设计保留为 future 参考，等官方群能力开放再启用。

## 后果

**正面**

- 通道已验证，最快可交付；
- 架构、Agent、RAG、数据层大部分复用；
- 隐私边界更简单：一人一域，不读群聊。

**负面**

- 失去群聊场景；
- 产品名/品牌“群栖”不再贴合，已改为“小栖 Xiaoqi”；
- 群聊需求只能通过“转发记录 → 纪要”等过渡方案满足。

## 备选

- 企业微信内部群：可行，但用户必须用企微；
- 企业微信外部群：官方不支持双向，非官方协议风险高；
- 等待 iLink 群能力：时间不可控。

## 后续

- 若做“转发群聊记录 → 纪要”，单独验证微信转发格式；
- 若 iLink/企业微信开放群事件，复用同一 Agent，只替换通道适配层。
