# ADR-0004：不模拟流式输出，typing + 一次性分段回复

- 状态：已接受（2026-11-06）
- 决策者：产品/架构
- 相关：设计文档 §3.3、§6.6

## 背景

LLM 产品习惯“逐字输出”，但微信个人号 Bot 的消息模型是“发送即固定”：

- 没有消息编辑 API；
- 没有流式消息类型；
- 频繁更新只能靠发多条新消息，体验是刷屏。

## 决策

- 生成期间用 `sendtyping` 表示“正在输入”，每 25 秒续一次，最多 90 秒；
- 生成完成后一次性发送，按 900 字符切分，最多 3 段；
- 超过 20 秒的任务，先发一条“收到，正在整理…”，每任务最多一次；
- 不做“逐字更新同一条消息”的伪流式。

## 后果

**正面**

- 不刷屏，符合微信群习惯；
- 发送逻辑简单，失败重试可控；
- 不会出现半截消息。

**负面**

- 首字延迟感知比流式差；
- 长回答要等全部生成完；
- typing 状态可能不被所有客户端展示。

**缓解**

- 用快速模型/缩短 prompt 降低首包时间；
- 长任务给一次进度提示；
- 目标 p95 < 10s，超过则优化检索/模型，而不是发更多消息。
